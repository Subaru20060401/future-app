## A. 確かめてから直すもの

  ただし単純に `isUsable` へ置き換えればよいわけではない（`isUsable` も「クライアントを作れるか」で、
  Google がトークンを受け付けるかまでは保証しない）。「表示用の連携状態」「操作前の復帰 `ensureAccess`」
  「API に拒否された後の `withFreshToken`」の役割で整理する。症状が出たら `authDiagnostics` の実値を見てから

## B. 重複（残り）

- `PlannedExpense` と `PlannedIncome` はクラスの形が同じ。ただし意味が違うので、形が同じだけで統合しない
  （別のAIも同意見）。入力シート（`planned_expense_sheet.dart` / `planned_income_sheet.dart`）の共通化は検討の余地あり
- 日付を文字にする小さな関数（`_fmt` など）が 5 ファイル。書式がそれぞれ違うので、まとめる価値は小さい

## 決まっていないこと

- **Gemini の課金**: Gemini API キーのプロジェクトに請求先アカウントが紐づいていて（有料 Tier 1・前払い残高 0 円）、
  API は `402 Payment Required` で止まっている。自動では無料枠に戻らない。
  無料で使うなら Google Cloud コンソールで「課金を無効にする」（プロジェクトのリンク解除）。
  解除すると無料枠になり、送ったデータが Google の改善に使われる（CLAUDE.md の Gemini 節）。
  本人がどちらにするか未決定
- **ローンの丸め方**: 画面も保存も `Loan` の計算（手数料込みの総額を先に丸めてから割る）にそろえた。
  これが実際の契約書の額と合うかは、ローン会社の明細で確かめていない
- **Android（Galaxy）での Google ログインは未確認**: 端末を Galaxy に変え、Chrome から PWA としてインストール済み。
  リダイレクト認証に切り替える `isPopupUnfriendly` は iPhone/iPad しか見ていない。
  Android で連携できなければ、ここに Android を足す
- **メールから予定を提案する案**: メール本文を Gemini に送ることになる。無料枠は個人情報を送るべきでない
  （規約）ので、有料にするか、AI を使わず定型メールからルールで日時を抜き出すかを先に決める
