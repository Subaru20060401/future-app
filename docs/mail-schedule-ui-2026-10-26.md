# メール予定のUI・UX改善

2026年10月26日の実装記録。メール予定の一覧と確認シートを改善。Galaxy実機確認は未実施。公開はmainへのpushに連動する既存のDeploy Webを使用する。

## 一覧

- 予定名・日時・場所・送信元をカード内で読む。長い予定名を1行に切り詰めない。
- 予定／シフト／変更／取消／見本／処理状態を文字で区別する。
- 終了時刻などの不足は、詳細を開く前に一覧でも知らせる。
- 確認待ち・保留・履歴の3タブを維持。文字拡大時はタブを横スクロールできる。
- 幅の上限は720px。スマホは1列、PCでも情報が横に離れすぎない。
- 画面右上と空状態から、既存の認証・取り込みサービスを使ってメールを再確認する。
- 確認中は重複操作を止める。結果は閉じられる画面内メッセージにし、一覧を覆わない。

## 内容の確認

- 最初に予定名・日時・場所を表示し、登録・保留・不要を選べる。
- 根拠と送信元の詳細は展開して読む。
- 日時・内容の編集欄は必要時に展開。必須項目が足りない候補やシフトは最初から開く。
- 日付・開始・終了はラベルと値を縦に配置し、タップ領域を確保する。
- シフトの勤務先・休憩入力、登録可否の判断は既存のAppStateを使う。
- 取消を反映する操作は色と文言で区別する。処理済みの履歴には編集欄を出さない。
- 保留・不要の直後は「元に戻す」を表示。履歴からも不要の判断を取り消せる。
- 登録済みや整理済みの候補を、戻し操作で確認待ちにはしない。
- 変更を登録するまで編集内容は画面内に保持し、閉じるボタンだけでは保存しない。

## 検証

架空データのWidgetテストで、幅320px・412px、文字サイズ150%、詳細の編集操作、不要の取り消し、履歴表示、空状態を確認した。描画したPNGで一覧と確認シートも目視確認した。

    flutter test
    flutter analyze lib/
    flutter test test/mail_schedule_ui_test.dart --dart-define=CAPTURE_MAIL_UI=true

最後のコマンドは `.dart_tool/mail_schedule_eval/ui/` に架空データの画面画像を出力する。通常の全体テストでは画像出力だけをスキップする。

WidgetテストはGalaxyのChromeそのものの検証ではない。公開後は、ブラウザの上下バー・実機キーボード・Google認証からの復帰・実データでのスクロールも確認する。
